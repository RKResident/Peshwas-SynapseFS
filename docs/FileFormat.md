# SynapseFS — File & Table Format Reference

Pure reference. No rationale — see `FORMAT.md` for *why*, `PLAN.md` for *when*.

All multi-byte integers are **little-endian**. All hashes are **BLAKE3-256**: raw 32
bytes in binary structures, lowercase hex (64 chars) in JSON.

---

## 1. INPUT — `.safetensors`

The format SynapseFS ingests and must reproduce byte-for-byte.

```
+--------------------------------+
| header_len : u64 LE   (8 bytes)|
+--------------------------------+
| header_json : header_len bytes |   UTF-8 JSON, space-padded (see 1.2)
+--------------------------------+
| data_region : rest of file     |   raw tensor bytes, no padding between tensors
+--------------------------------+
```

### 1.1 Header JSON schema

```json
{
  "__metadata__": { "<key>": "<string>" },
  "<tensor-name>": {
    "dtype": "F16",
    "shape": [4, 2],
    "data_offsets": [8, 24]
  }
}
```

| Field | Type | Notes |
|---|---|---|
| `__metadata__` | object, optional | String→string only. Always emitted **first** when present. |
| `dtype` | string | See §1.4 |
| `shape` | array of int | Row-major. `[]` = scalar. |
| `data_offsets` | `[begin, end)` | **Relative to the start of `data_region`**, not to the file. `end - begin` must equal `prod(shape) * itemsize`. |

### 1.2 Three properties that break byte-exactness if you re-serialize

Verified against a real file generated by `safetensors` 0.8.0:

1. **The header is space-padded.** `header_len` = 168 for a JSON body of 163 bytes —
   5 trailing `0x20` bytes. The padding aligns `8 + header_len` to an 8-byte boundary
   (`(8+168) % 8 == 0`), so the data region is aligned for `mmap`.
2. **Tensor keys are sorted alphabetically**, not in insertion order. The demo file was
   written as `{weight, bias}` and serialized as `__metadata__`, `layer1.bias`,
   `layer1.weight`. `data_offsets` follow the *sorted* order.
3. **`__metadata__` is emitted first**, before any tensor key.

> **Rule: store `[header_len ‖ header_json]` verbatim as a `header` object and replay
> it. Never rebuild it from a parsed dict.** Any of the three properties above will
> differ under re-serialization and the output will not be byte-identical.

### 1.3 Worked example (real bytes)

Two tensors: `layer1.weight` = `arange(8).reshape(4,2)` fp16, `layer1.bias` =
`[0.5, -0.5, 1.0, -0.0]` fp16, metadata `{"format":"pt"}`. Total file: **200 bytes**.

```
00000000  a8 00 00 00 00 00 00 00  7b 22 5f 5f 6d 65 74 61  |........{"__meta|
00000010  64 61 74 61 5f 5f 22 3a  7b 22 66 6f 72 6d 61 74  |data__":{"format|
00000020  22 3a 22 70 74 22 7d 2c  22 6c 61 79 65 72 31 2e  |":"pt"},"layer1.|
00000030  62 69 61 73 22 3a 7b 22  64 74 79 70 65 22 3a 22  |bias":{"dtype":"|
00000040  46 31 36 22 2c 22 73 68  61 70 65 22 3a 5b 34 5d  |F16","shape":[4]|
00000050  2c 22 64 61 74 61 5f 6f  66 66 73 65 74 73 22 3a  |,"data_offsets":|
          ...
```

- `header_len` = `a8 00 00 00 00 00 00 00` = **168**
- Header JSON occupies `[8, 176)`; the last 5 bytes are spaces
- `data_region` starts at **176**, is 24 bytes:

```
offset 176:  00 38  00 b8  00 3c  00 80     <- layer1.bias   data_offsets [0,8)
offset 184:  00 00  00 3c  00 40  00 42     <- layer1.weight data_offsets [8,24)
offset 192:  00 44  00 45  00 46  00 47
```

Decoded (LE u16): bias = `0x3800 0xB800 0x3C00 0x8000` = `0.5, -0.5, 1.0, -0.0`.
Note `-0.0` is `0x8000` and `+0.0` is `0x0000` — **distinct patterns that must survive
round-trip**. Never normalize signed zero.

### 1.4 dtype table

| `dtype` | itemsize | numpy | In PS scope |
|---|---|---|---|
| `F16` | 2 | `float16` | ✅ primary |
| `BF16` | 2 | — (view as `uint16`) | ✅ primary |
| `F32` | 4 | `float32` | ⚠️ may appear in small fixtures |
| `F64` | 8 | `float64` | unlikely |
| `I64` / `I32` / `I16` / `I8` | 8/4/2/1 | signed ints | buffers only |
| `U8` / `BOOL` | 1 | `uint8` / `bool` | rare |

`BF16` has no numpy dtype. Read it as `uint16` and never convert to float in the
storage or codec path.

## 2. INPUT — `config.json`

Accompanies each evaluated checkpoint; defines graph topology. Shape varies by
architecture; parse into the topology IR rather than binding to specific key names.

Minimum fields the parser must locate (by whatever key the fixture uses):

| Concept | Typical keys |
|---|---|
| Layer sequence / count | `num_hidden_layers`, `depths`, `layers` |
| Hidden width per layer | `hidden_size`, `hidden_sizes`, `width` |
| Layer type | `model_type`, `architectures`, per-layer `type` |
| Conv geometry | `kernel_size`, `stride`, `channels` |

Referenced from `checkpoint-manifest.topology_config_hash` as a BLAKE3 of the raw
`config.json` bytes.

## 3. Repository layout

```
<SYNAPSE_DIR>/
├── objects/
│   ├── tmp/<random>                 write staging; deleted on startup
│   ├── <hh>/<hash>                  loose objects, sharded by first hash byte
│   └── pack/
│       ├── pack-<hash>.pack         sealed chunk container  (§5)
│       ├── pack-<hash>.idx          its index               (§6)
│       └── order                    newline-separated pack hashes, newest first
├── refs/
│   └── heads/<branch>               text file: one 64-char commit hash + "\n"
└── HEAD                             "ref: refs/heads/main\n"  or  "<hash>\n"
```

| Object kind | Storage | Format |
|---|---|---|
| `chunk` | pack | binary payload (§7) |
| `header` | loose | raw bytes (§4.1) |
| `permutation` | loose | raw int32 array (§4.2) |
| `dictionary` | loose | zstd dictionary blob |
| `tensor-manifest` | loose | JSON (§4.3) |
| `checkpoint-manifest` | loose | JSON (§4.4) |
| `commit` | loose | JSON (§4.5) |

## 4. Loose object formats

### 4.1 `header`

Raw bytes, copied verbatim from the source file's `[0, 8 + header_len)`. No wrapper,
no framing. Object hash = BLAKE3 of those bytes.

### 4.2 `permutation`

Packed `int32` LE array, no header. `count = filesize / 4`.

```
+---------+---------+---------+-----
| p[0]    | p[1]    | p[2]    | ...     each 4 bytes, int32 LE
+---------+---------+---------+-----
```

Semantics depend on the referencing field:

| Referenced as | `p[i]` means |
|---|---|
| `base_row_permutation` | the **base** row index that target row `i` was diffed against |
| `base_col_permutation` | the **base** column-block index that target column-block `i` was diffed against |

Example — π = `[2, 0, 3, 1]` (12 bytes... 16 bytes):

```
02 00 00 00  00 00 00 00  03 00 00 00  01 00 00 00
```

### 4.3 `tensor-manifest`

```json
{
  "name": "layer1.weight",
  "dtype": "F16",
  "shape": [4096, 4096],
  "base_tensor_manifest": "9f2c...a1",
  "base_row_permutation": "3b71...0e",
  "base_col_permutation": null,
  "col_block_size": 1,
  "chunks": [
    {"row_start": 0,    "row_end": 511,  "encoding": "delta-zigzag-zstd", "object": "aa01...ff"},
    {"row_start": 512,  "row_end": 1023, "encoding": "raw-zstd",          "object": "bb02...ee"},
    {"row_start": 1024, "row_end": 4095, "encoding": "delta-zigzag-zstd", "object": "cc03...dd"}
  ]
}
```

| Field | Type | Notes |
|---|---|---|
| `name` | string | Must match the key in the source header exactly |
| `dtype` | string | §1.4 |
| `shape` | int[] | As in the source header |
| `base_tensor_manifest` | hash \| `null` | `null` ⇒ stored in full; no delta |
| `base_row_permutation` | hash \| `null` | `null` ⇒ identity. **Fast path.** |
| `base_col_permutation` | hash \| `null` | `null` ⇒ identity |
| `col_block_size` | int ≥ 1 | §4.3.1 |
| `chunks[].row_start` | int | **Inclusive**, logical row index |
| `chunks[].row_end` | int | **Inclusive**, logical row index |
| `chunks[].encoding` | enum | §7 |
| `chunks[].object` | hash | Chunk content hash; resolve via pack index |

**Row indices are logical** — the row order of the target `.safetensors` file. There is
no stored-vs-logical translation. Chunks partition dim 0 exhaustively and without
overlap; `chunks[0].row_start == 0` and `chunks[-1].row_end == shape[0] - 1`.

#### 4.3.1 `col_block_size`

A column permutation moves contiguous blocks of this many columns as a unit.

| Tensor | Logical 2D shape | `col_block_size` |
|---|---|---|
| Linear `[out, in]` | `[out, in]` | `1` |
| Conv2d `[out_ch, in_ch, kh, kw]` | `[out_ch, in_ch·kh·kw]` | `kh · kw` |
| Linear following a conv flatten | `[out, in_ch·H·W]` | `H · W` |

Column block `c` occupies columns `[c·col_block_size, (c+1)·col_block_size)`.

### 4.4 `checkpoint-manifest`

```json
{
  "header_object": "1a2b...cd",
  "tensors": {
    "layer1.bias":   "44de...01",
    "layer1.weight": "9f2c...a1"
  },
  "topology_config_hash": "77aa...bb"
}
```

### 4.5 `commit`

```json
{
  "checkpoint_manifest": "5e6f...12",
  "parents": ["0a1b...99"],
  "timestamp": "2026-08-25T12:00:00Z",
  "message": "epoch 3 checkpoint"
}
```

| Field | Notes |
|---|---|
| `parents` | `[]` root · `[h]` normal · `[h1, h2, ...]` merge |
| `timestamp` | RFC 3339, UTC, `Z` suffix |

**JSON canonicalization (all manifest/commit objects):** UTF-8, `separators=(',',':')`,
`sort_keys=True`, no trailing newline. Required — otherwise identical content hashes
differently and dedup breaks.

## 5. Packfile — `pack-<hash>.pack`

```
+========== HEADER (52 bytes) ==========+
| 0   8   magic       "SYNPACK\0"       |
| 8   4   version     u32 = 1           |
| 12  4   flags       u32, bit0=has dict|
| 16  4   count       u32               |
| 20  32  dict_hash   blake3 or zeros   |
+========== RECORDS × count ============+
| 32  content_hash   blake3 (uncompressed content) |
| 4   stored_len     u32                          |
| 4   plain_len      u32                          |
| N   payload        stored_len bytes  (§7)       |
+========== TRAILER (32 bytes) =========+
| blake3 of bytes [0, EOF-32)           |
+=======================================+
```

- Records are back-to-back from offset 52; record stride = `40 + stored_len`.
- **Index offsets point at `payload`**, not at the record header. The header for a
  payload at offset `o` occupies `[o-40, o)`.
- Packs are **immutable once sealed**. Never appended to.
- A lost `.idx` is rebuildable by scanning records from offset 52.

---

## 6. Pack index — `pack-<hash>.idx`

Designed to be `mmap`ed and binary-searched in place.

```
offset        size    field
------        ----    ---------------------------------------------
0             8       magic      "SYNIDX\0\0"
8             4       version    u32 = 1
12            4       count      u32 = N
16            32      pack_hash  blake3 of the .pack
48            1024    fanout     256 × u32, cumulative
1072          32N     hashes     raw 32-byte hashes, ascending
1072+32N      8N      offsets    u64, payload offset into .pack
1072+40N      4N      stored_len u32
1072+44N      4N      plain_len  u32
1072+48N      8N      checksum   first 8 bytes of blake3(payload bytes)
EOF-32        32      trailer    blake3 of bytes [0, EOF-32)
```

- Entry cost: **56 bytes**. 280,000 chunks ≈ 15.7 MB.
- `fanout[b]` = count of entries whose `hash[0] <= b`. `fanout[255] == count`.
- Arrays are **parallel**, not interleaved — a search touches only `hashes`.

### Lookup

```python
b  = h[0]
lo = 0 if b == 0 else fanout[b - 1]
hi = fanout[b]
i  = bisect(hashes, h, lo, hi)          # compare 32-byte memoryview slices
# -> offsets[i], stored_len[i], plain_len[i], checksum[i]
```

Multi-pack: probe each mmapped `.idx` in `objects/pack/order` sequence (newest first).

> **Do not build a Python dict of hex-string keys.** 280k entries costs 50–80 MB
> resident against a graded peak-RSS metric. Binary-search the mmap.

## 7. Chunk payload encodings

`encoding` in a tensor-manifest chunk entry selects the decode path.

| `encoding` | Payload is | Decode |
|---|---|---|
| `raw` | Uncompressed tensor bytes for the row range | memcpy |
| `raw-zstd` | zstd frame over tensor bytes | zstd decompress |
| `delta-zigzag-zstd` | zstd frame over zigzag-varint deltas | §7.1 |

If the pack's `flags` bit 0 is set, zstd frames were compressed with the dictionary at
`dict_hash` and must be decompressed with it.

### 7.1 `delta-zigzag-zstd`

**Encode** (target chunk `B`, corresponding base rows `A` after applying
`base_row_permutation` / `base_col_permutation`):

```
1. key(x) = bits(x) ^ 0x8000        if sign bit clear      # 16-bit dtypes
   key(x) = ~bits(x)   (uint16)     if sign bit set

2. delta  = int32(key(B)) - int32(key(A))                  # elementwise

3. zz     = (delta << 1) ^ (delta >> 31)                   # zigzag -> uint32
   varint/bitpack zz                       <-- CONTENT HASH COVERS THIS STREAM

4. zstd(step-3 bytes)                      <-- this is the pack payload
```

Generalize step 1 to width `w` as `1 << (w-1)`.

**Decode:** zstd → un-varint → un-zigzag → `key(B) = delta + key(A)` → invert `key()`
→ reinterpret as dtype.

```
invert: bits = key ^ 0x8000       if key & 0x8000       # was non-negative
        bits = ~key   (uint16)    otherwise
```

### 7.2 Worked example (verified)

`A = [0.5, -0.5, 1.0, -0.0]`, `B = [0.5009765625, -0.49951171875, 1.0009765625, -0.0]`, F16:

| | elem 0 | elem 1 | elem 2 | elem 3 |
|---|---|---|---|---|
| `bits(A)` | `0x3800` | `0xB800` | `0x3C00` | `0x8000` |
| `bits(B)` | `0x3802` | `0xB7FE` | `0x3C01` | `0x8000` |
| `key(A)` | 47104 | 18431 | 48128 | 32767 |
| `key(B)` | 47106 | 18433 | 48129 | 32767 |
| `delta` | **2** | **2** | **1** | **0** |
| `zigzag` | 4 | 4 | 2 | 0 |

Round-trip verified bit-exact. Note element 3: `-0.0` maps to key 32767 with delta 0
and reconstructs as `0x8000`, not `0x0000`.

## 8. `refs/` and `HEAD`

| File | Content |
|---|---|
| `refs/heads/<branch>` | 64 hex chars + `\n` |
| `HEAD` (attached) | `ref: refs/heads/<branch>\n` |
| `HEAD` (detached) | 64 hex chars + `\n` |

Written temp→fsync→rename→fsync-dir. Always the **last** write in any operation.

## 9. Quick lookup — reconstruct byte range `[a, b)` of tensor `T`

```
1. HEAD/ref            -> commit hash
2. commit              -> checkpoint_manifest hash
3. checkpoint-manifest -> tensors[T] -> tensor-manifest M
4. rows = byte range [a,b) mapped through M.shape and itemsize(M.dtype)
5. select M.chunks entries overlapping `rows`
6. for each: pack-index lookup(object) -> (pack, offset, stored_len, plain_len)
             pread(pack, stored_len, offset) -> decode per M.chunks[].encoding
7. if M.base_tensor_manifest is null: done
   else: recurse for ONLY the required base rows
           base rows = π[i] for i in rows   (contiguous if base_row_permutation is null)
         then apply §7.1 decode
```

Reconstructing the full file = `header_object bytes ‖ concat(tensors in header key order)`.
Tensor placement in `data_region` is given by each tensor's `data_offsets` in the header —
**use those, do not recompute the layout.**
